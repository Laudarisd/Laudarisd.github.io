      Agent Collection - Tool-Using Assistants and Retrieval Pipelines

      A collection of small, focused agent systems: assistants that call tools, workflows that run on their own, and retrieval pipelines that give a language model the documents it needs. Each one is a working piece of code that solves one task, built for research and for production use.

      Keywords

      DomainAI agents · LLM
      PiecesTool-using assistants · workflows · RAG
      Model accessHosted APIs and local models
      LanguagePython

      1. Introduction

      A language model on its own can only write text. An agent is a model with a loop around it: it reads the request, decides which tool to call, reads the result, and keeps going until the task is done. This collection holds the pieces I keep reusing for that loop: a tool-calling assistant, workflow runners that chain steps without a person in between, and retrieval pipelines that fetch the right documents before the model answers.

      flowchart LR
    U[User request]:::input --> A[Agent
      plans the steps]:::agent
    A --> T[Tools
      search · files · APIs]:::tool
    T --> A
    A --> R[(Retrieval
      documents, vectors)]:::store
    R --> A
    A --> O[Answer or
      completed task]:::output

      2. Goal

      Goal

      • Keep one tested, reusable implementation of each agent pattern instead of rewriting it per project.
      • Make tool use safe and traceable: every call and result is logged, and anything that changes data asks first.
      • Let the same agent code run against a hosted API or a local model with no other change.

      Agent Collection - Tool을 쓰는 어시스턴트와 Retrieval Pipeline

      작고 목적이 분명한 Agent 시스템 모음이에요. Tool을 호출하는 어시스턴트, 혼자 돌아가는 워크플로, 언어 모델에 필요한 문서를 찾아 주는 Retrieval Pipeline이에요. 하나하나가 과제 하나를 해결하는 동작하는 코드이고, 연구와 실무 둘 다에 써요.

      1. 소개

      언어 모델 혼자서는 글만 써요. Agent는 모델 주위에 루프를 두른 거예요. 요청을 읽고, 어떤 Tool을 부를지 정하고, 결과를 읽고, 일이 끝날 때까지 계속해요. 이 모음에는 그 루프에 계속 다시 쓰는 부품들이 있어요. Tool을 호출하는 어시스턴트, 사람 없이 단계를 이어 가는 워크플로 러너, 모델이 답하기 전에 맞는 문서를 가져오는 Retrieval Pipeline이에요.

      flowchart LR
    U[사용자 요청]:::input --> A[Agent
      단계 계획]:::agent
    A --> T[Tool
      검색 · 파일 · API]:::tool
    T --> A
    A --> R[(Retrieval
      문서, 벡터)]:::store
    R --> A
    A --> O[답 또는
      완료된 작업]:::output

      2. 목표

      목표

      • Agent 패턴마다 테스트된 구현 하나를 두고, 프로젝트마다 다시 만들지 않아요.
      • Tool 사용을 안전하고 추적 가능하게 해요. 모든 호출과 결과를 기록하고, 데이터를 바꾸는 일은 먼저 물어봐요.
      • 같은 Agent 코드가 Hosted API에서도 로컬 모델에서도 바꾸지 않고 돌아가게 해요.
